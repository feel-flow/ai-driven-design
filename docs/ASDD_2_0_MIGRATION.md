# AI仕様駆動開発2.0 導入・移行ガイド

[2.0標準仕様](ASDD_2_0.md) に沿って、目的と進め方を対話で決める。既存の `/init-docs` やテンプレートのURLは維持する。2.0設定がない既存プロジェクトは、移行するまで従来動作のままとする。

## 1. 対応版と作業範囲を確認する

仕様文書の公開と、スキル・テンプレートの配布は別である。導入前に [全体Epic #523](https://github.com/feel-flow/ai-spec-driven-development/issues/523)、[公開ff-dev-toolkit](https://github.com/feel-flow/ff-dev-toolkit)、そのリリース情報を確認し、使用する版に `asdd-init` と `asdd-work` があるか確認する。

本リポジトリの旧文書frontmatterにある `version: 2.0.0` は、各文書の改訂番号であり、新しいASDD 2.0の対応表示ではない。旧コマンド、MCP、配布テンプレートの一部が使えるだけで、全体が2.0に適合したとは判定しない。対応版の生成・検証契約を確認できない場合は、従来導入を維持し、未対応部分を記録する。

| 導入経路             | 使い方と境界                                                                                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公式プラグイン       | 対象ホストのネイティブmarketplace機能で導入し、スキルが読み込まれることを確認する。SKILL.mdを利用先へ複製しない                                                            |
| テンプレート直接利用 | 既存URLを維持する。2.0版は [同期Issue #525](https://github.com/feel-flow/ai-spec-driven-development/issues/525) で出力元の版・コミット・ライセンス情報と一致検証を確認する |
| MCP                  | 選択した文書構成を対象に検索・参照する。MCP登録だけで初期化スキルやHookが導入されたとは扱わない                                                                            |

ホストごとの導入コマンド、Hook対応、設定形式は利用する版の公式実装を参照する。このリポジトリをcloneしただけでプラグイン導入が済んだとは扱わない。

初回試用実装では、成果物の履歴保存を選ぶ場合、Issueへの記録と保存対象の指定も必要になる。記録なし、Issue記録のみ、Issue記録と履歴保存の組合せから選ぶ。これは初回実装の対応範囲であり、利用者に設定JSONの編集を求めるものではない。

手編集と生成差分を自動で統合する再設定には、GitHub連携の有無にかかわらずローカルGitが必要である。未導入の環境では、その統合を実行できたと報告せず、導入または衝突を保護した手動調整を案内する。

## 2. 新規プロジェクトを始める

対応版を確認したうえで、`asdd-init` に例えば次のように依頼する。スキルの呼び出し表記はホストに従う。

> 仕事の案内文を作りたいです。自分が使うので市民開発向けに、必要なことを会話で確認しながら始めてください。作業と成果物を後から確認できるようにしたいです。

AIは目的・利用者・完成条件を整理し、保存先・範囲、推奨構成、有効になる自動処理を提示する。利用者は必要な部分だけ選ぶ。市民開発なら短い `docs/MASTER.md`、Issueと履歴保存、成果物に応じた確認提案から開始できる。

開発者向けでも、PoCか継続運用か、実データ・公開の影響から構成を選ぶ。ACEと自動振り返りは新規構成で初期無効。レビューやテストの強さとは独立に変更できる。

生成後は、作成したファイル、有効な機能、未決事項と次の作業を確認する。`asdd-init --check` で整合を読み取り専用で検査し、「初期構築が完了」と「利用・公開可能」を別々に確認する。

## 3. 既存プロジェクトを移行する

1. **現在の状態を記録する。** 文書の配置・決定事項、AI設定、Hook、スクリプト、CI、リポジトリの保存・PR方針を読み、作業中の差分も確認する。
2. **継続する方針と見直す候補を分ける。** 既に合意した規則は維持する。カバレッジ80%、Result型などが雛形由来なのか実際の合意なのかを確認し、変更候補を提示する。
3. **構成と変更範囲を合意する。** 利用スタイル、段階、文書構成、個別機能、GitHub記録先・保存範囲を選ぶ。7文書があるという理由だけで削除・再配置しない。
4. **対応版の生成処理を使う。** `.asdd/config.json` と生成管理情報を作る。JSONの具体的なキーは実装版のスキーマに従い、手作業で推測した設定を投入しない。
5. **手編集と衝突を確認して反映する。** 無条件の上書き・削除をしない。設定と生成物を一組として履歴に残し、復元可能な状態を保持する。
6. **切替結果を確認する。** `--check`、選択した構成の [適合条件](ASDD_2_0_CONFORMANCE.md)、実ホスト上の動作を確認する。ACE等を無効にした場合は、旧Hookが実行や督促をしないことまで確かめる。

組織ルール・ブランチ保護はプロファイル切替で緩めない。従来の7文書検証を2.0最小構成へそのまま適用してファイル不足にしない。旧検証しか利用できない場合は、対応完了までの制約として記録する。

## 4. 日常利用・再設定・復旧

| 操作                 | 進め方                                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------- |
| 作業を頼む           | `asdd-work` に目的を伝える。既存Issueを確認し、一つの目的・成果物の完成条件を記録して進める                |
| 状況を聞く           | 「今どうなっている？」と聞く。最新のIssueと関連履歴から、確認日時・現在地・未決事項を確認する              |
| 設定を変える         | `asdd-init` を再実行し、現設定と生成物を読み、変更差分を合意して適用する                                   |
| 保存に失敗した       | 保存済みと未同期を区別する。既存のIssue・記録・コミットを照合し、復旧後に重複なく再開する                  |
| 生成が途中で止まった | 現在の設定・管理情報・実ファイルを照合する。存在するファイルを初期状態と決めつけず、衝突を示して再開する   |
| 以前の構成へ戻す     | 自分の変更範囲の設定・管理情報・生成物を履歴と照合して復元する。利用者の後続編集を保護し、整合を再確認する |

`.asdd/config.json` だけを消して移行を取り消さない。旧機能が復活したり、設定と生成物が不一致になったりしないよう、有効なHook・CIを含めて確認する。既に記録したIssueや成果物の履歴は、設定変更だけでは削除しない。

## 5. 既存ガイド・実装・書籍との関係

| 対象                                                                          | 2.0での扱い                                                                             |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| [概念と実践](AI_SPEC_DRIVEN_DEVELOPMENT.md)・[実践ガイド](PRACTICAL_GUIDE.md) | 従来の文書分割・実例を読むために保持。7ファイル必須などは新規2.0構成へ適用しない        |
| [運用ガイド](OPERATIONAL_GUIDE.md)                                            | 従来構成の運用手順を保持。2.0の最小文書検証・設定切替は本仕様と対応版実装に従う         |
| `/init-docs`・`/setup-ai-config`・`/validate-docs`                            | 個別機能の入口として維持。2.0対応時は設定の合意内容を引き継ぐ                           |
| 複数AIレビュー・ACE・自動化                                                   | 任意機能。導入方法の説明を、全利用先での有効化指示と解釈しない                          |
| 書籍                                                                          | 既存の参照URLを保持。改訂版の手順は公開済み実装と照合し、提出・販売状態を別々に確認する |

方法論・スキル・テンプレート・書籍は同じ仕様を参照しつつ、マージ済み、配布済み、利用確認済みを個別に記録する。方法論文書のPRをマージしただけで2.0全体を公開完了と報告しない。
